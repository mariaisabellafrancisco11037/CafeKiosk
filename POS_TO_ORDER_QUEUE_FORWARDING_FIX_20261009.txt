CafeKiosk POS -> Order Queue forwarding fix (2026-10-09)

Root cause fixed:
- POS order numbers used a localStorage sequence (POS-1001, POS-1002, ...).
- Incognito/new devices restarted at POS-1001.
- Existing orders with the same number were treated as duplicates, so no new Pending order was inserted.

Changes:
1. POS now generates a device-independent unique order number.
2. Backend duplicate detection is scoped to cafe_id + order number.
3. Inventory duplicate detection is also cafe-scoped.
4. Backend reads the exact saved order back from the same cafe before claiming it was forwarded.
5. POS only shows the success confirmation if queueVerified=true.
6. Socket.IO + GET /api/orders polling remain the delivery/sync mechanisms.
7. Order Queue layout/CSS is not modified by this fix.
